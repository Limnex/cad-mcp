# AutoCAD 原生圆角实测记录

日期：2026-10-21。分支：`feature/native-fillet`。

## 环境和证据范围

- Windows，AutoCAD 已由用户手动打开；COM 版本回读为 `25.1s (LMS Tech)`。
- 验证对象为当前分支的 `cad_fillet` 工具函数及 AutoCAD 后端，通过真实 COM 调用执行原生 `FILLET`。
- 每组测试仅使用本实例新建的临时图纸，不保存并在结束时关闭；测试前后核对原有图纸的名称、路径、保存状态与实体数量。
- 本轮没有重新安装或重启用户已连接的旧 MCP 服务；当前分支源码的实测不能当作已连接服务已更新的证明。

|---|---|

| 锁层、不同标高、倾斜直线、错误拾取标高 | 拒绝，图形和设置不变 |
| 短边配过大半径 | 无几何变化时报错，不撤销前一次操作 |
| 平行线请求 R2、原生结果半径不符 | 拒绝并真实撤销，几何与设置恢复 |
| 零半径连接 | 直线延伸到共同端点，无新圆弧 |
| R0.001 与 Z=7 | 圆角半径及标高回读正确 |
| 同一多段线的相邻线段 | 普通坐标、百万级远坐标、旋转 UCS 均成功 |
| 拾取点落在另一图元 | 句柄核对拒绝，图形和实际视图恢复 |

三种写入后报错的用例均在注入前记录了本次命令的完成标记、修改前后坐标和新增句柄，确认几何确实改变；随后触发异常。最终均满足 `rollback_status=succeeded`，并核对完整临时模型空间的几何、系统设置及实际视图恢复。

## 本轮修复

1. 同一多段线重复传实体名时，AutoCAD 报“图元无法用自身圆角”。改用原生按点选取，并在执行前核对实际命中的句柄。
2. 圆/圆弧组合的原有选取方式可能无法构造圆角。改用 AutoCAD 原生最近点计算得到曲线上的选取点，再核对句柄并执行。
3. COM 的 ActiveViewport 属性曾保留缓存，不能证明画面已恢复。改为原生上一视图恢复，并读取实际视图系统变量核验。
4. 故障注入曾在没有证明实际写入时触发，无法验证真实撤销。新增完成标记及几何变化前置检查，严格撤销断言通过后才记录用例成功。

## 遗留问题与配置收尾

- 将基础实测与边界实测合并到同一进程时，公共图层查询曾出现 `<unknown>.Item`；具体原因尚未定位。最终边界测试独立运行整套通过，不能据此声称该公共查询问题已修复。
- 诊断曾无法还原日志路径，后来按用户明确选择，改为本机 AutoCAD 用户配置目录并回读核验；日志记录保持关闭。
- 原有图纸的记录状态保持一致，所有本轮临时图纸已关闭且未保存。
- DXF 圆角留待后续版本，本轮未实现。

## 复现方式

先手动打开 AutoCAD，并获得实机写入授权。分别启动下列两个测试进程，不连接用户业务图纸：

```powershell
$env:CAD_MCP_RUN_ACAD_INTEGRATION = '1'
uv run pytest tests/integration/test_fillet_acad.py -m acad -x -s
uv run pytest tests/integration/test_fillet_edges_acad.py -m acad -x -s
Remove-Item Env:CAD_MCP_RUN_ACAD_INTEGRATION
```

本地详细证据为 `.cache/fillet-live-edges.json` 与 `.cache/fillet-edges-final-console.log`，包含实际坐标、半径、完成标记及撤销状态。缓存文件不提交到仓库。
